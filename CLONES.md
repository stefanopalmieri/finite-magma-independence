# The Clone-Theory Bridge — v2, revised after external review

**Status**: working notes, 2026-07-22, revised the same day following an
adversarial clone-theoretic review. The review's corrections are adopted
below; §4 records what v1 overstated and why. Companion script:
`scripts/clone_experiment.py`. Machine-checked anchors in

## 1. Dictionary (corrected terminology)

Fix a finite groupoid (A, ·). Standard vocabulary:

- λ : a ↦ L_a (L_a(x) = a·x) is the **left regular representation**; its
  injectivity — our "extensionality" — is *left reductivity / left
  faithfulness*. The naming map is classical; what this framework adds is
  the package: carrier = name space, injective internal naming, semantic
  disciplines imposed on the image, and comparison against the polynomial
  operations.
- Rows L_a and columns R_b(x) = x·b are **unary polynomial operations**
  (parameters allowed). The set of all unary polynomials is the **unary
  part of the polynomial clone** — a monoid under composition, *not* a
  clone (v1 misnamed it). It properly contains the translation monoid
  generated by {L_a, R_b}: e.g., x ↦ x·x duplicates the variable.
  (`scripts/clone_experiment.py` computes the full unary polynomial
  monoid: closure of {id, constants} under composition and pointwise ·.)
- "**Polynomially complete**" is used throughout (not "functionally/
  Sheffer-complete"): the polynomial clone is all of 𝒪_A. Criterion used
  (|A| ≥ 3, Słupecki): all unary operations present plus an operation with
  image of size ≥ 3 and essential arity ≥ 2 (surjectivity of · supplies
  the image condition in our examples).

## 2. The results, at their correct strength

**(i) Verified separation (reproducible finite verification;** script
output not independently certified — the Lean-checked results are only
those of §2(ii)**).** Finite D-groupoids can be polynomially complete:

- `dNoS4` (the tight D⇏S witness in `E2PM.lean`, N=4): unary polynomial
  monoid = all 256 unary maps; · surjective, essentially binary ⇒
  polynomially complete, and satisfies D.
- `comp5` (frozen in the script, N=5): E2PM + D, no retraction pair, no
  ICP, unsorted; unary polynomial monoid = all 3125 maps ⇒ polynomially
  complete.

*Scope caveat (per review)*: "polynomial completeness does not imply
internal naming of all unary polynomials" is **generic** — n rows can
never cover n^n maps. The non-generic content is that polynomial
completeness is compatible **with D specifically**, whose axioms one
might have expected to constrain the generated clone. (They constrain
only the named rows; the absorber columns and higher compositions
remain wild.) Also noted: expressive power *varies widely* across
D-groupoids (270/3125 for witness5 up to 3125/3125 for comp5); no
formal independence claim is made.

**(ii) Structural obstruction (machine-checked, any cardinality).**
The sharp form of the completeness wall involves no counting, because it
concerns naming only |A| specific maps:

> **In every dichotomic 2-pointed applicative structure — finite or
> infinite — {R_b : b ∈ A} ⊄ {L_a : a ∈ A}**: some column is named by no
> row. Consequently no D-structure admits unary combinatory abstraction;
> in particular, it admits no *pair* of S- and K-combinators satisfying
> the usual equations. (The obstruction rules out a jointly adequate
> (S, K) basis — the thrush is definable from the pair — and does not by
> itself exclude an element separately satisfying only the S- or only the
> K-equation.)

Lean: `d_leaves_a_column_unnamed` (contrapositive of
`flip_blocks_dichotomy`), `CompletenessWall.lean`, stated over an
arbitrary carrier. Proof mechanism: D's own axioms manufacture a mixed
column (τ·x₀ absorber-valued, y₀·x₀ core-valued); a row naming that
column would be a mixed element.

**Calling card** (per the review's recommended formulation): *there
exists a finite polynomially complete groupoid satisfying D; nevertheless,
in every D-groupoid, at least one right translation is not a left
translation, so no D-groupoid is combinatorially complete.* The first
half is computational (script), the second machine-checked.

**(iii) Research program (Rosenberg-inspired taxonomy — an analogy, not
an embedding).** Rosenberg's six relational types suggest candidate
*unary disciplines on the named translation family*:

- Sorting = the named non-classifiers are uniformly compatible with the
  sort equivalence θ (relation type: nontrivial equivalence);
- hygiene = shift commutes with quote, i.e., preserves graph(quote's core
  action) (relation type: fixed-point-free prime-order permutation —
  quote is a fixed-point-free involution in the swap world).

Gaps that block any stronger "embedding" claim (per review, adopted):
row-wise preservation of θ does not make · itself preserve θ (that would
need q(x·y) = q(x)·q(y)-style conditions); one named row commuting with
quote says nothing about the polynomial clone lying in Pol(graph q);
quote's action is a permutation of the *core*, not of the carrier; and
the unary fragments of Rosenberg's classes may not retain what
distinguishes the maximal clones. The remaining four relation types
(bounded order, prime affine, central, h-regular) are a **menu of
candidate disciplines**, to be presented as Rosenberg-inspired until
their interaction with the generated clone is actually established.

## 3. The realization problem, correctly posed

v1's "which subsets of the unary part arise as left-translation
families?" is trivial: any injectively indexed family (f_a)_{a∈A} defines
a·x := f_a(x) with exactly those rows, and each f_a is automatically a
unary polynomial of the resulting groupoid. The non-trivial versions fix
the ambient structure first:

> Given a **constantive** clone C on A (one containing all constants —
> necessary, since polynomial clones contain them), classify injective
> families F ⊆ C^(1), indexed by A, such that the groupoid a·x := f_a(x)
> generates C as its polynomial clone — or satisfies a prescribed
> internalization property (prescribed right translations, prescribed
> translation monoid, prescribed named polynomials beyond the rows).
> Equivalently, for arbitrary C, take the target to be the clone generated
> by C together with all constants.

This, plus the D-obstruction of §2(ii), is the honest form of the
framework's subject: *constrained realization of translation families
inside a clone*.

## 4. Corrections adopted from review (v1 → v2)

1. "Separation of internal/external completeness" narrowed: the generic
   counting part is not new; the D-compatibility and the counting-free
   column obstruction are the content.
2. "Structural embedding into Rosenberg" demoted to taxonomy-by-analogy.
3. "Naming map as undeveloped gap object" retracted; the map is the
   classical left regular representation (left reductivity); the possibly
   novel part is the package and the constrained realization problem (§3).
4. Terminology: unary polynomial *monoid*; *polynomially* complete.
5. Parity results acknowledged as standard equivariance/centralizer facts
   (blocks exchanged by an involution are equinumerous; a fixed-point-free
   involution 2-cycles any invariant block; centralizer C_p ≀ S_m) — their
   interest here is only what they force in this setting.
6. Before claiming the magma case "unexplored," a literature pass is owed
   on: *translation monoid of a groupoid*, *multiplication monoid/group*,
   *regular representations of groupoids*, *left reductive groupoids*,
   translational hulls (semigroups).

## 5. Remaining expert questions (sharpened)

1. Is the following obstruction known for groupoids, under any of the
   §4.6 headings? Assume: (i) two distinct elements z₁, z₂ with
   z₁·x = z₁ and z₂·x = z₂ for all x; (ii) an element τ ∉ {z₁, z₂} with
   τ·x ∈ {z₁, z₂} for all x; (iii) elements y₀, x₀ ∉ {z₁, z₂} with
   y₀·x₀ ∉ {z₁, z₂}; (iv) every y ∉ {z₁, z₂} satisfies either
   y·x ∈ {z₁, z₂} for all core x or y·x ∉ {z₁, z₂} for all core x.
   Conclusion: {R_b : b ∈ A} ⊄ {L_a : a ∈ A}.
2. Is the constrained realization problem of §3 studied anywhere (for
   C = 𝒪_A it touches polynomially complete groupoids; for general C it
   seems open)?
3. Do the unary-discipline analogues of Rosenberg's other four relation
   types each admit an involution-style interaction theorem with the
   retraction pair, as types (4) and (2) did (sorting involution;
   hygiene)?
4. (Opened by the S/K precision above.) Can an *infinite* D-structure
   carry a lone K-combinator (k·a·b = a, no S)? K alone names all
   constant maps as rows — apparently harmless to D — and K-infinity
   only forbids finite carriers. If yes, the wall is genuinely about the
   pair; if no, a stronger single-combinator obstruction exists.

## 6. Bottom line (revised)

The connection survives review at reduced but firmer strength: the
framework is not clone theory and not subsumed by it; its defensible
exports are the calling-card pair in §2 (one computational witness, one
machine-checked obstruction, jointly separating polynomial from
combinatory completeness *in the presence of D*), and its defensible
import is Rosenberg's classification as a heuristic menu for the
connecting-axiom program. Claims beyond that await the literature pass
and the clone-interaction results named in §2(iii).
